# ADR 0003：本地账户、会话与数据隔离

- 状态：已接受
- 日期：2026-08-28

## 背景

早期版本用请求参数中的 `user_id` 区分学习记录。浏览器端可以正常工作，但任何调用者都能修改参数冒充另一位学习者；模型配置和本地草稿也没有明确的账户边界。

## 决策

1. 使用 SQLite 保存账户、会话和安全审计事件。密码使用标准库 `hashlib.scrypt` 加盐摘要，不保存明文，也不引入额外运行时依赖。
2. 登录后发放随机不透明会话令牌：服务端只保存 SHA-256 摘要，浏览器使用 `HttpOnly`、`SameSite=Lax` 的会话 Cookie；写请求同时要求可读 CSRF Cookie 对应的 `X-CSRF-Token`。
3. 每个私有 API 从会话身份取得 `user_id`，忽略客户端提交的同名字段。题目作答、附件、笔记、模板覆盖、训练会话、模拟考、LLM 配置和学习统计均按账户查询；管理员只能访问身份元数据、审计和部署设置。
4. 第一个注册账户自动成为管理员。注册时把旧版本 `local-user` 工作区迁移到该账户，并复制旧的模型配置；迁移后不再允许无会话访问私有 API。
5. 管理员可启用/停用账户、调整角色和查看审计；停用账户会撤销其全部会话，系统始终保留至少一名启用管理员。

## 后果与边界

- 会话可撤销、密码修改会退出所有设备；服务重启后会话仍保留至过期，便于本地学习连续使用。
- 登录和注册按来源 IP 做轻量速率限制；安全响应头、图片文件头校验、附件归属校验和输入长度限制在 API 层执行。
- 本地开发模式允许旧工作区在首个账户注册前继续使用，便于升级；该兼容窗口不会在已有账户后绕过认证。
- SQLite 适合单机/小规模本地部署。若要公网多进程部署，应把会话、速率限制和密钥存储迁移到受控服务，并在反向代理启用 HTTPS、限流和备份策略。
